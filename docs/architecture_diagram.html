Lane 1 · Outside the server

Residents and services

Everything the site talks to over the internet. None of it stores the conversation.

Resident

Opens 311.scurrycat.ca on any device and describes the issue and where it is. The page says to call 911 for emergencies.

Chat page index.html

Picks the model: Ollama by default, or OpenRouter. An OpenRouter key stays in the page's memory for the session and goes with each message; the server never stores or logs it.

Cloudflare

HTTPS and edge caching. The home-docker tunnel carries requests to the team server with no open router ports; cloudflared hands them to 127.0.0.1:8311.

Ollama on the host GPU

qwen3:4b-instruct on the team server, outside the container (host.docker.internal:11434). No charge per call; up while the yick1 session is logged in.

OpenRouter

Commercial models (default claude-haiku-5.5) on the resident's own key. Returns each call's price, logged as cost_usd.

Lane 2 · Docker container

One chat turn

The FastAPI app in the gilead-311 container. Steps 2, 4, 6 and 7 run the interaction tree in flow.yaml.

Every step and every tree node is logged, masked, so /admin can replay the turn.

1

Screen the message

Redacts card numbers and similar before anything else sees them (D2), and notes which pattern lists matched: emergency, crisis, abuse, prompt injection.

2

Message tree

Emergencies get the 911 reply (E1); crisis or abuse goes to a person (E8, E7); a suspected injection adds a warning for the model (S1).

3

Call the model

System prompt, the conversation and 7 tool schemas go to the chosen model. At most 8 round trips per message; a failed call is retried once (F1).

4

Before-tool tree

Checks each tool call first and can block it:

  • policy looked up before fields or a ticket (A2)
  • one ticket per issue (A8)
  • status needs ticket number and postal code (D5)
5

Run the tool

classifier, policy_lookup, search_tickets, create_ticket, get_status, handoff, kb_search. One retry; still failing goes to a person (E9).

6

After-tool tree

Reads the result: open duplicate, use it (C6); ticket created, confirm the exact ID (M3); fields missing, ask one at a time (M2) and hand off past the limit (E6). Adds guidance for the model.

7

Reply tree

Checks the model's answer before the resident sees it: no invented ticket IDs or false "created" claims (M3), rule tags stripped (D8), commitments flagged (C1).

8

Answer and log

Sends the reply. Each step, tool call and tree node goes to interaction_events with model, tokens, cost and latency; all text masked (D6).

AUTO

Config cache and sync thread config.py · rag/ingest.py

Loads every config file from Supabase at start and holds it in memory for steps 2 to 7. Reloads at once when /admin saves; every 60 s the sync thread re-reads the table and re-chunks edited knowledge-base documents. If Supabase is briefly down it keeps the last copy; if config never loaded, chat answers 503. The repo holds no copy the site could fall back on, so nothing goes stale.

Lane 3 · Team in /admin

Watch and change

No login yet (prototype); everything shown is masked.

No redeploy: a saved change is used from the next message on.

A

Interactions

Replay any conversation step by step, with the tree beside it and the path taken highlighted.

B

Tickets and Handoffs

Live lists; change status, add notes, keep a history of who did what.

C

Analytics

Requests per hour, day or month; reply time per model, Ollama against commercial; running cost against doing it by hand.

DTEAM

Review and decide

The team spots a wrong turn, a missed rule, a slow model or a gap in the knowledge base, and decides what to change.

Most fixes are edits on this page. A new kind of check, tool or tab needs code (lane 4).

E

Flow

Rewire, reword or switch off steps of the interaction tree.

F

Files

policy.yaml, guardrails.yaml, prompts, app.yaml (models, cost assumptions).

G

Knowledge base

Add, edit or hide documents; changed ones are re-chunked at once.

HAUTO

Check and save

A save is refused if:

  • the YAML doesn't parse or a key the code reads is gone
  • a pattern isn't a valid regex
  • the tree loops, points nowhere, or drops a hard rule
  • the system prompt won't render

Otherwise it is stored with a revision and the cache reloads.

Lane 4 · Code and deploy

Code changes

Only new code needs a deploy. The container keeps no files of its own.

TEAM

Change the code

In the repo. pytest runs 70 tests on an in-memory store with the fixture config in tests/fixtures/config/; tests never touch Supabase.

Push to main

TerraIncognito-sudo/311_Agent_MMAI on GitHub. Decisions are logged in docs/decisions.md.

TEAM

Rebuild on the server

On 192.168.1.149: git pull, then docker compose up -d --build. The container restarts on its own after a reboot.

AUTO

New version live

Pages link scripts by content hash, so Cloudflare never serves an old one. /api/health reports whether config loaded from Supabase.

Gilead 311: from a resident's message to a ticket

311 Intake Agent · how a message is screened, run through the interaction tree and a model, answered and logged in Supabase, how the team watches and changes the agent from /admin, how the training data and classifiers are made offline, and where each edge case is caught. Live at 311.scurrycat.ca · 8 service codes · 60 policy rules, 30 of them hard.

Lane 1 · Outside the server

Residents and services

Everything the site talks to over the internet. None of it stores the conversation.

Resident

Opens 311.scurrycat.ca on any device and describes the issue and where it is. The page says to call 911 for emergencies.

Chat page index.html

Picks the model (Ollama by default, or OpenRouter) and the classifier. An OpenRouter key stays in the page's memory for the session and goes with each message; the server never stores or logs it.

Cloudflare

HTTPS and edge caching. The home-docker tunnel carries requests to the team server with no open router ports; cloudflared hands them to 127.0.0.1:8311.

Ollama on the host GPU

qwen3:4b-instruct on the team server, outside the container (host.docker.internal:11434). No charge per call; up while the yick1 session is logged in.

OpenRouter

Commercial models (default claude-haiku-5.5) on the resident's own key. Returns each call's price, logged as cost_usd.

Lane 2 · Docker container

One chat turn

The FastAPI app in the gilead-311 container. Steps 2, 4, 6 and 7 run the interaction tree in flow.yaml; a failed model call or no answer in 8 round trips runs its own tree and hands off (E9, M4).

Every step and every tree node is logged, masked, so /admin can replay the turn.

1

Screen the message

Redacts card numbers and similar before anything else sees them (D2), and notes which pattern lists matched: emergency, crisis, abuse, prompt injection.

2

Message tree, then classify

Emergencies get the 911 reply (E1); crisis or abuse goes to a person (E8, E7); a suspected injection adds a warning for the model (S1). Then the chosen classifier (keyword stub or fine-tuned) picks the service code in code; unsure gets one clarifying question (E3, F2). The code goes to the model with the message.

3

Call the model

System prompt, the conversation and 6 tool schemas go to the chosen model. At most 8 round trips per message; a failed call is retried once (F1).

4

Before-tool tree

Checks each tool call first and can block it:

  • policy looked up before a ticket (A2)
  • search for duplicates first (A10)
  • one ticket per issue (A8); none for a status check (A12)
  • escalation trigger: hand off (E2)
  • injection in arguments (S5)
  • status needs ticket number and postal code (D5)
5

Run the tool

policy_lookup, search_tickets, create_ticket, get_status, handoff, kb_search. One retry; still failing goes to a person (E9).

6

After-tool tree

Reads the result: open duplicate, use it (C6); ticket created, confirm the exact ID (M3); fields missing, ask one at a time (M2) and hand off past the limit (E6). Adds guidance for the model.

7

Reply tree

Checks the model's answer before the resident sees it: no invented ticket IDs or false "created" claims (M3), rule tags stripped (D8), commitments flagged (C1).

8

Answer and log

Sends the reply. Each step, tool call and tree node goes to interaction_events with model, tokens, cost and latency; all text masked (D6).

AUTO

Config cache and sync thread config.py · rag/ingest.py

Loads every config file from Supabase at start and holds it in memory for steps 2 to 7. Reloads at once when /admin saves; every 60 s the sync thread re-reads the table and re-chunks edited knowledge-base documents. If Supabase is briefly down it keeps the last copy; if config never loaded, chat answers 503. The repo holds no copy the site could fall back on, so nothing goes stale.

Lane 3 · Team in /admin

Watch and change

No login yet (prototype); everything shown is masked.

No redeploy: a saved change is used from the next message on.

A

Interactions

Replay any conversation step by step, with the tree beside it and the path taken highlighted. Re-run it on another model or classifier; tickets and handoffs in a re-run are simulated.

B

Tickets and Handoffs

Live lists; change status, add notes, keep a history of who did what.

C

Analytics

Requests per hour, day or month; reply time per model; classifiers (unsure rate, confidence, time); re-runs side by side (speed, tokens, decisions); running cost against doing it by hand.

DTEAM

Review and decide

The team spots a wrong turn, a missed rule, a slow model or a gap in the knowledge base, and decides what to change.

Most fixes are edits on this page. A new kind of check, tool, tab or a retrained classifier needs code or a deploy (lane 4).

E

Flow

Rewire, reword or switch off steps of the interaction tree.

F

Files

policy.yaml, guardrails.yaml, prompts, app.yaml (models, cost assumptions).

G

Knowledge base

Add, edit or hide documents; changed ones are re-chunked at once.

HAUTO

Check and save

A save is refused if:

  • the YAML doesn't parse or a key the code reads is gone
  • a pattern isn't a valid regex
  • the tree loops, points nowhere, or drops a hard rule
  • the system prompt won't render

Otherwise it is stored with a revision and the cache reloads.

Lane 4 · Code and deploy

Code changes

Only new code or new classifier weights need a deploy. The container keeps no data of its own.

TEAM

Change the code

In the repo. pytest runs 228 tests on an in-memory store with the fixture config in tests/fixtures/config/; tests never touch Supabase.

Push to main

TerraIncognito-sudo/311_Agent_MMAI on GitHub. Decisions are logged in docs/decisions.md.

TEAM

Rebuild on the server

On 192.168.1.149: git pull, then docker compose up -d --build. Fine-tuned classifier weights are copied to src/models/fine_tuning by hand and mounted read-only. The container restarts on its own after a reboot.

AUTO

New version live

Pages link scripts by content hash, so Cloudflare never serves an old one. /api/health reports whether config loaded from Supabase.

Lane 5 · Offline, on Kaggle

Data and classifiers

Done before the site runs, outside it. Generated data, keys and test sets stay off GitHub; code, notebooks, LOCK.md and results/ are committed.

1TEAM

Policy and hand-written cases

Operating Policy v1.0 (policy.yaml) fixes the 10 route codes, 20 escalation triggers, 10 outcomes and the edge cases. The team writes 105 test messages by hand; the policy adds 84 edge cases. Both stay in data/protected/.

2

Generate synthetic messages

src/data_gen/synth_311_pipeline.py (prompt 311-v5). Each scenario fixes the gold label; 3 OpenRouter models at 4 temperatures write the message; Faker fills fake names, addresses and IDs.

  • 50% easy, 30% hard (look-alikes, near-miss duplicates, triggers), 20% adversarial
  • QC with reasons; near-copies of protected cases dropped
  • split by scenario template; adversarial test rows sealed
  • the team reads review.csv; 3,295 kept
3

Fine-tune the classifiers

NB-05 on a Kaggle GPU: DistilRoBERTa and ModernBERT-base on train.jsonl, 85/15 split by template, 5 epochs, best by macro-F1. Validation macro-F1 0.88 and 0.86.

NB-04 runs prompted Haiku and Sonnet baselines on the same 343 rows (macro-F1 0.82 to 0.86).

4

Lock the test sets

NB-03: held-out (774 cases: generated, hand-written and policy edge cases), production-like (340) and adversarial (118). Leakage checks against train; each file's SHA-256 in data/test/LOCK.md. Nothing is tuned on them.

5

Evaluate

run.py eval classify scores a classifier; eval agent runs the whole agent through the same turn as lane 2. Results go to results/; make reproduce rebuilds them from cached answers.

Edge cases

Where each is caught

Bold numbers are the steps in lane 2.

CODE a check in code; the model can't skip it

PROMPT only the system prompt asks for it

CODE

Emergency

Gas smell, sparking wire, crash with injuries.

1 emergency patterns → 2 message tree 911 reply, no ticket (E1). Look-alikes (a leaking hydrant, a fire pit) don't match and go on as normal; the training data has them on purpose.
CODE

Crisis, or asks for a person

Self-harm, distress, a complaint about staff, legal threats.

1 pattern lists → 2 message tree Handed to a person, with the crisis line for self-harm (E8, E7).
CODE

Prompt injection

"Ignore your rules", hidden instructions, instructions inside tool arguments.

1 injection list → 2 warns the model; 4 checks tool arguments Treated as text, never followed (S1, S5).
CODE

Personal data

SIN, card, health card, date of birth, passport.

1 redacted; 5 create_ticket refuses it; 8 logs masked Never stored (D2); names, phones and addresses are masked in every log (D6).
CODE

Unclear category

Classifier confidence under 0.70, top two within 0.10, or no valid code.

2 after-classifier tree One clarifying question; still unsure, a person (E3, F2).
CODE

Hazard trigger

One of the 20 triggers: a deep pothole, an injured dog, no heat, near a school.

4 trigger gate before create_ticket Handed off with the draft ticket (E2); a vague location is asked for once first.
CODE

Missing or wrong details

A field missing, a location like "near the big tree", a value not on the list.

5 create_ticket refuses → 6 after-tool tree Asks for one field at a time (M2, A11, A4); after two tries, a person (E6).
CODE

Duplicate

An open ticket already covers it, within that code's radius and days.

4 must search first → 6 after-tool tree Points to the open ticket, files no second one (A10, C6); one ticket per request (A8).
CODE

Status check

"Any update on 311-2026-000123?"

4 blocks a new ticket, needs the postal code; 5 get_status Status only with the ticket number and its postal code (D5, A12); a number plus a new problem gets one question.
CODE

Out of scope or private property

A streetlight, a tree in a backyard, dumping on private land.

5 policy_lookup routes OOS; create_ticket refuses not-handled cases No ticket; says what it can help with and offers a person (A8, E10).
CODE

A reply it shouldn't send

An invented ticket ID, a false "created", a date, visit, priority, fine or refund.

7 reply tree Invented IDs or claims go to a person (M3); promises are replaced with approved wording (C1 to C4, C7); rule tags stripped (D8).
CODE

Something fails

A tool or model fails twice, no answer in 8 round trips, config unreachable.

3, 5 retry once → failure trees A person, never a claimed ticket (E9, F3); step limit (M4); no config, chat answers 503 (F4).
PROMPT

Not in English

About 18% of the generated messages.

3 system prompt Handed off as handoff_language (M6); hazards and emergencies keep their safety outcome.
PROMPT

Several issues or conflicting details

"Pothole and my streetlight is out", two different addresses.

3 system prompt Handles each; more than two, or still conflicting after one question, goes to a person (E4, E5).
PROMPT

Pressure or abuse

"Your chatbot promised", a claimed councillor, abusive language.

3 system prompt; 7 catches promises Approved wording, no other residents' data (S2, S3, S7); search_tickets returns no names (D3).

How they're tested

The 84 policy edge cases and all 20 triggers, each with look-alikes, are in the locked held-out set; injection, PII and pressure cases are in the sealed adversarial set (lane 5). pytest checks each tree and tool rule with a scripted model.
